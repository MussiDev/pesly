## Findings by rule

- ✅ F-SAST-01 Hardcoded secrets (CWE-798): the scan for password, secret, token and key names over the changed sources found none added by this ticket. The only environment value the job reads is `RECURRING_JOB_INTERVAL_SECONDS`, already validated by `parseWorkerEnv` (`apps/api/src/shared/config/env.ts`, comment-only change).
- ✅ F-SAST-02 SQL injection (CWE-89): the publisher uses Drizzle `onConflictDoNothing` and bound operators (`apps/api/src/notices/infrastructure/db/drizzle-statement-reminder-publisher.ts:65` for the insert, `:41` to `:54` for `published`); the cross-owner source uses `innerJoin`, `gt`, `orderBy` and `limit` (`apps/api/src/credit-cards/infrastructure/db/drizzle-statement-reminder-source.ts:43` to `:46`); the only `sql` templates added are static check constraints over column references (`apps/api/src/credit-cards/infrastructure/db/schema.ts:44`, `apps/api/src/notices/infrastructure/db/schema.ts:32`); the migration is static DDL (`apps/api/drizzle/0030_card_statement_reminders.sql:1`). No `db.execute`, `sql.raw` or string concatenation into a query.
- ✅ F-SAST-03 OS command injection (CWE-78): no `child_process`, `exec` or `spawn` in the changed code.
- ✅ F-SAST-04 Insecure deserialization (CWE-502): the only new input is the optional `reminderDays` key of the existing strict Zod bodies (`packages/shared/src/credit-cards/credit-card.ts:41`: integer from 0 to 30); nothing is deserialized beyond `JSON` through the shared validator, and the job reads typed rows from the database only.
- ✅ F-SAST-05 Path traversal (CWE-22): no file path is built from input; the web request builder never builds a path, and the client refuses a card id such as `..` through `resourcePath` without a request (`apps/web/test/api-client-credit-cards.test.ts`, `refuses ".." on update without a request`).
- ✅ F-SAST-06 XSS (CWE-79): the reminder field renders its label, hint and error text from the i18n catalogs, and the notice text (which carries a user-chosen card name) is shown by the existing notices screen as a plain text node; no `dangerouslySetInnerHTML` or `innerHTML` in the changed code (see R-13).
- ✅ F-SAST-07 SSRF (CWE-918): no outbound request added; the web client calls the existing API base only and the job talks to the database only.
- ✅ F-SAST-08 Broken cryptography (CWE-327): no cryptography added or used.
- ✅ F-SAST-09 Debug mode in production (CWE-489): no debug flag added; an idle pass logs at debug level and a pass that created or failed at info (`apps/api/src/credit-cards/infrastructure/jobs/statement-reminder-job.ts:62` to `:64`).
- ✅ F-SAST-10 Logging sensitive data (CWE-532): failures log card id and error class name only, de-duplicated per `cardId|errorName` (`apps/api/src/credit-cards/infrastructure/jobs/statement-reminder-job.ts:25` to `:30`); the pass-level error logs only the class name (`:77` to `:78`); the use case reports `{ cardId, errorName }` (`apps/api/src/credit-cards/application/create-statement-reminders.ts:128`); the route audit lines carry request id, user id and card id and never the card name. Tests assert no card name, amount, language or zone in any logged field (`statement-reminders.test.ts`, `statement-reminder-job.test.ts`, `credit-card-routes.test.ts`).
- ✅ F-SAST-11 Unrestricted upload (CWE-434): not applicable, no upload surface.
- ✅ F-SAST-12 Missing CSRF protection (CWE-352): no new endpoint; the reminder setting travels on the existing `POST /credit-cards` and `PATCH /credit-cards/:id`, behind `requireSession`, `requireVerifiedEmail` and the cookie policy of every authenticated route. The job has no HTTP surface.
- ✅ F-SAST-13 Critical/High CVE in a dependency: `pnpm audit --prod --audit-level high` reported "No known vulnerabilities found"; no dependency was added.
- ✅ F-SAST-14 Incomplete input validation (CWE-20): `reminderDays` is validated by `cardReminderDaysSchema` before any handler runs (`packages/shared/src/credit-cards/credit-card.ts:41`), re-checked by the database (`credit_cards_reminder_days_check`, `apps/api/src/credit-cards/infrastructure/db/schema.ts:44`) and by the web parser; sad-path tests cover -1, 31, a fraction, a string, `null`, `NaN` and `Infinity` at the schema, the route (400), the database and the web builder, plus no session (401), an unverified email (403) and another user's card (404).
